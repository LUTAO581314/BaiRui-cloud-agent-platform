# 可观测页设计说明

## 页面定位

可观测是当前用户对其 Agent 进行运行诊断的独立页面，覆盖指标、调用链路 Trace、脱敏日志与异常告警。它不展示其他用户、主机或容器的原始运行数据。

## 职责边界

- 总览仪表盘：跨 Agent 聚合摘要和近期活动，仅用于判断整体情况。
- 智能体管理：项目配置、运行状态和会话入口，不展示性能诊断指标。
- 会话管理：用户对话及其工具调用上下文。
- 可观测：按 Agent 检索和诊断调用表现、链路、日志与异常。

## 后续页面范围

- 统一筛选：时间范围（今日、近 7 天、近 30 天）与 Agent。
- 指标摘要：调用量、Token、平均延迟、成功率；延迟分位值 P50、P95、P99 位于趋势面板。
- 调用趋势：请求量、延迟与成功率的时间序列，附图例和无数据状态。
- 最近 Trace：Trace ID、Agent、会话、开始时间、耗时、状态；点击进入单条链路详情。
- 脱敏日志：时间、级别、组件、事件与关联 Trace ID，不展示原始密钥、完整用户内容或调试转储。
- 告警：异常摘要、影响 Agent、最近发生时间、状态和处理入口。

## MVP 页面组织

首版采用单页面“诊断工作台”，不拆分左侧子页面。页面从上到下组织为：统一筛选区、指标摘要、调用趋势、最近 Trace、脱敏日志和告警列表。筛选区固定支持时间范围（今日、近 7 天、近 30 天）与 Agent，其他模块根据筛选条件同步刷新。

- 指标摘要和趋势用于快速判断性能变化。
- 最近 Trace、脱敏日志和告警用于定位具体问题。
- Trace 行提供详情入口，后续可扩展为独立 Trace 详情页。
- 日志行提供关联 Trace 的跳转入口，暂不单独拆出日志详情页。
- 无数据、加载中和查询失败状态需要在各模块内明确展示。

首版不加入主机/容器监控、跨用户数据、原始日志导出、复杂告警编排或实时流式追踪，避免与平台运维侧能力及总览仪表盘重复。

## 已确认的产品规则

- **数据隔离**：所有模块仅查询当前账号所属 Agent 的数据，不展示其他用户、主机、容器或平台级数据。主机与容器资源遥测属于管理员能力，不纳入用户可观测页。
- **调用量口径**：遵循平台能力文档中的“请求、Token、延迟、失败”用量事实；调用量按 Agent 请求/运行记录统计，失败请求单独计数。
- **指标定义**：Token 分为输入 Token、输出 Token 和总 Token；成功率只统计 Agent 最终响应成功；延迟从请求开始计算到完整响应结束。
- **时间粒度**：今日按小时聚合，近 7 天和近 30 天按天聚合；没有数据时显示空状态，不用示例曲线填充。
- **筛选与刷新**：支持“全部 Agent”和单个 Agent，支持按 Trace ID 或会话 ID 关键词搜索；筛选条件联动刷新所有模块。MVP 只提供手动刷新，并显示最后更新时间。
- **Trace 与日志详情**：允许查看完整请求参数和响应内容，但日志始终脱敏；Trace ID 可复制。脱敏范围不得包含 API Key、Token、密码、完整用户内容或其他秘密。
- **告警**：MVP 只展示告警，不支持创建规则；状态固定为“未处理 / 已确认 / 已恢复”。
- **统一状态**：各模块统一处理加载中、无数据、查询失败和接口未接入状态，并在页面显示可供开发定位的错误信息。
- **权限**：当前按单用户控制台处理，不实现复杂的角色权限模型，但接口仍必须按当前账号隔离数据。
