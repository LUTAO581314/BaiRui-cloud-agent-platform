# Git 提交规范

本仓库使用约定式提交（Conventional Commits），提交信息使用中文，便于变更检索、发布说明生成和问题定位。

## 提交格式

```text
<类型>(<范围>): <简短描述>

<可选正文>

<可选脚注>
```

首行保持简洁，描述使用动词开头，不以句号结尾。范围应指向受影响模块，例如 `console`、`api`、`docs` 或 `server`。

## 类型

- `feat`：新增用户可见功能
- `fix`：修复错误或行为回归
- `refactor`：重构，不改变外部行为
- `docs`：只修改文档
- `style`：格式或视觉样式调整，不改变业务逻辑
- `test`：新增或调整测试
- `build`：构建、依赖或工具链调整
- `chore`：其他维护性变更

存在不兼容变更时，在类型后添加 `!`，并在脚注说明 `BREAKING CHANGE`。

## 示例

```text
feat(console): 新增可观测诊断工作台
fix(console): 补充接口失败和渲染异常提示
docs(observability): 记录用户侧指标与数据隔离规则
build(console): 更新 Vite 构建配置
```

## 提交前检查

1. 只提交与当前任务相关的源代码、文档和配置。
2. 不提交 `dist/`、`output/`、`.playwright-cli/`、密钥、日志和真实用户数据。
3. 在 `apps/console-mvp/` 执行 `npm run build`；若输出目录被运行中的服务占用，记录原因并使用等效的 `npx vite build --emptyOutDir false` 完成验证。
4. 视觉或交互修改需检查桌面和移动视口，并在提交说明中写明验证结果。

## 提交粒度

一个提交应对应一个清晰目的。功能实现、独立修复和纯文档变更尽量拆分；若代码与其必要文档不可分离，可以合并为一个提交。
